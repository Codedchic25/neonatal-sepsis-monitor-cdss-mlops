## 🗄️ Relational Data Layer Architecture (SQLite Matrix) - Part 2

#### A. Seeded Time-Step Ingestion (`Execute Telemetry Step`)

When a clinician advances the timeline (+1h), the system executes a relative historical lookback query on the `crp` and `pct` matrices.
*   **If historical data exists:** It computes randomized micro-fluctuations using uniform distribution bounds (`np.random.uniform(-2.0, 5.0)`) for CRP and (`-0.2, 0.8`) for PCT to maintain physiological progression continuity.
*   **If database is empty:** The script auto-seeds the baseline arrays using normal neonatal ranges to generate an immediate stable entry-point.
*   **UI Synchronization:** A trailing server-side `st.rerun()` forces an instantaneous canvas redraw, compiling the raw query output array straight into the static `st.line_chart` rendering mechanism.

#### B. Therapeutic Clearance Intervention (`Simulate Injection Therapy`)

When an antibiotic dose is delivered, the transaction bypasses standard physiological micro-fluctuations. It forcefully injects a clean baseline vector (`CRP: 4.2 mg/L`, `PCT: 0.4 ng/mL`, `HR: 140 bpm`) into the row array. This triggers an immediate downward trajectory slope on the line charts, documenting successful medical clearance.

#### C. Absolute Data Minimization Purge (`Clinical Reset System`)

To comply with strict data residency policies and prevent long-term local host storage footprint tracking, the system exposes an administrative reset vector. Activating this routine executes a synchronous atomic truncate command:
```sql
DELETE FROM telemetry;
VACUUM;
```
This forces all local pointer matrices back to safe, hard-coded initialization fallbacks and resets the global security session flags (`st.session_state["cyber_alert_triggered"] = False`).

### 3. Thread-Safe Context Isolation Bounds

To mitigate race conditions and database locks during concurrent interface interactions, the SQLite connection pooling limits are explicitly bound using local process isolation constraints:
```python
conn = sqlite3.connect("sepsis_v2.db", check_same_thread=False)
```
This isolated operational runtime ensures that database cursors remain entirely bounded within individual execution threads, protecting the relational matrix against cross-session data bleeding.
